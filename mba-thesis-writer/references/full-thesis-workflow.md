# 完整MBA论文的连续执行

适用于完整论文、新建全文或全稿深度修订。一次委托连续完成研究、全文、内部复核和Word交付，分段保存并接续执行；单章、表格和格式任务按原范围处理。

## 启动时解决会导致全篇返工的事项

先读现有资料，集中核对题目/开题是否确认、培养单位与适用模板、论文类型、研究对象与期间、核心问题与预期成果、数据取得范围、需要的交付版本、导师已给意见。学籍与签字等非研究字段可以留到定稿核对；实质性研究变更按已有授权处理。不要重新向用户索取文件中已有信息。

问卷任务按 [问卷设计与分析](questionnaire-and-simulation.md)推进。需要先成稿后补真实结果时，使用 [临时工作稿流程](temporary-results-workflow.md)整合临时图表和条件式分析，记录替换任务并继续各章写作。

对核心研究问题做一次取证可行性判断：

- 现有内部或公开证据可支持研究目标：开始分析与写作。公开案例资料足够时，不强求企业内部数据。
- 可从正规公开来源补齐：主动检索、核验、形成证据，再进入需要它的分析；不只提交搜索关键词让用户查找。
- 当前证据只能支持一部分：立即完成可支持内容，集中说明准确缺项、取得方式、影响的结论和可继续的章节。行业平均值不能替代企业实测，计划访谈不能变成已完成访谈。
- 原方案在数据或方法上不可执行：形成可审查的替代设计与影响范围，按用户已有授权执行；需要新选择时继续不受影响的工作。

启动时说明本次交付的篇章范围和证据状态，集中取得必要补充材料，随研究进展更新交付状态。

## 从研究问题安排全文

在已有project.json中按需记录各章的目的、对应研究问题、所需证据/分析产物、关键论断、拟用图表和与后章的关系。篇幅按学校实际口径及各章任务安排，核心分析和成果应有足够展开空间；不设通用固定章数、字数配额或统一模型清单。

专题研究确保每个重要问题能连到证据、成因、解释、方案及评价；描述型案例重在真实过程、机制与竞争解释；决策型案例重在真实困境、备选方案及选择依据。目录必须服务这种逻辑，避免先套目录再填常识。每章完成的是实质正文，章末结论为下一章提供已建立的事实或判断。

完整论文通常需要中英文题名与摘要、关键词、正文、参考文献及按模板适用的前后置内容。实际使用的调查工具、编码说明、补充计算和详细方案按需要放附录。附录不收录未开展的调查结果或无关原始材料。摘要中的对象、研究期间、方法、有效样本、核心发现和贡献与正文逐项核对，英文保留相同的限定强度。

## 分析如何达到论文深度

先说明问题的判断依据：与哪个目标、历史基线、业务要求或可比对象比较，差异是否同口径，影响范围和管理后果是什么。把数量与比例、总体与分组、当期与累计、名义与实际、计划与实绩分开；如指标总量上升而比率下降，应同时解释两者。原因未知时不能从单一结果趋势跳到组织或员工成因。

对关键成因提出能被资料检验的解释。理论应说明变量/机制及可观察证据，而不是只放在理论介绍章。对每个解释寻找支持证据、反例和替代解释；结论分别标清事实、受支持解释和待检验假设。访谈看法不自动等于客观原因；比较相关性不自动等于因果关系。诊断要落实到本研究的流程、岗位、决策、资源或约束。

文献综述按研究问题或机制综合主要共识、分歧、方法与情境边界，说明本研究为什么需要及如何使用这些成果。经典理论与适用的新研究各司其职，文献量取决于覆盖要求，不按任意年代/语种比例补篇数。研究空白须有检索与比较依据，不把“尚无本企业研究”直接写成理论空白。

有定量分析时，先核验观察单位、字段和分母，保存清洗与分析程序，报告实际有效样本、估计量、单位和不确定性。按具体方法检查模型前提、缺失、异常、偏差、效应大小和必要稳健性；检验不适用时解释原因，不机械堆信效度或显著性。定性研究保留记录—编码—主题—论断定位、相反意见和研究者解释过程。混合研究说明两类证据在哪个结论上相互印证或冲突。

## 方案需要能被管理者审查

每项核心措施明确针对哪个已分析问题、通过什么机制起作用、为何优于可行备选或维持现状，以及责任、资源、时间和先后依赖。问题优先级可以依据影响、紧迫性和执行约束比较，不能编造专家评分或权重。不同措施不能互相争用同一资源而不解释安排。

预算、目标、收益和工期有实际依据时给出可复算估计及假设；不确定时给合理情景范围与敏感性，不伪装成已批准预算。KPI明确公式、单位、基期、数据来源、频次、责任和目标依据，避免只有“提高满意度”等方向。未实施方案提供试点、过程监测与结果评价设计，不声称已经取得效果；简单前后比较的归因局限要写清。

描述型案例若成果是实践机制或理论总结，改为说明支持事件、适用条件和推广边界，不硬塞一章不存在的实施效果。

## 连续写作与内部返修

按 [正文与补充说明](manuscript-and-supplement.md)保持论文正文与编辑事项分离。先完成可自行解决的问题，将确需补证或用户材料的事项写入独立文档，给出准确位置、处理方法及关联修改；正文保持连续论证。

用户已要求全文时，在研究路径明确后继续完成全部适用章节，不默认每写一章请求一次批准。复杂分析、长文生成和排版分批执行并保存文件，记录完成位置及下一步；恢复后接续最新版本。仅在研究实质、关键数据取得或外部授权确需用户决定时集中沟通。

先完成证据与分析核心，随后完成方案/案例总结、评价及结论，再回校绪论、综述和中英文摘要。主稿使用稳定章节与文献ID管理，多文件写作最终合并到一个完整稿。统一企业称谓、匿名方式、术语与英文译名、研究期间、样本量、单位、关键数字和措施名称；正文、图表、摘要、结论用同一核验依据。

内部复核至少覆盖以下实质问题，作为实际审读而非仅填pass：

| 复核 | 需要找到的证据或位置 |
|---|---|
| 研究问题是否真正回答 | 各问题对应的分析结论及其证据，不只在结论重述问题 |
| 重要判断是否站得住 | 原始定位、适用推断、替代解释及边界 |
| 理论与方法是否用上 | 核心分析中的实际解释/计算及方法条件 |
| 实践成果是否可行 | 问题对应、备选取舍、资源约束和实际评价设计 |
| 全文是否一致 | 核心事实/数字/术语/引用跨章、图表、中英文摘要一致 |
| 成稿是否完整 | 适用前后置内容、全部正文、文献、必要附录及实际Word文件 |

对可修复问题完成返修并重查受影响项。检索后仍缺可靠证据时，缩小结论或明确取证任务；质检结果分别记录工具检查、实际审读与导师反馈。

## Word成稿与最终文件

交付前逐项落实 [成品交付要求](delivery-contract.md)，将正文、图表、证据和实际复核对应到同一稿件版本。

Agent使用当前环境文档工具把文字、图表、文献和适用模板栏目装配成完整DOCX，配合表格及审计脚本核对样式、分节、页眉页码、字段和目录，再渲染全部页面。

直接核对正文实际引用和文后列表。顺序编码用 [引用检查工具](citation-audit.md)定位问题；著者—出版年、自动编号及复杂引用按实际显示值核查，结合现行国标复核题录字段、标点和语义支持。

将已确定目录中的核心章标题逐项传给 `audit_docx.py --expect-heading`（可重复参数）。标题使用文档中实际段落文字；Word自动生成的章序号不属于文字时不传入。检查根据段落大纲级别及样式继承定位标题，排除普通目录副本，发现缺章、重复标题或章内只有标题时报告错误。没有正确设置大纲级别时先修复标题样式。`text_present` 仅表示存在非标题文字，不能证明内容充实；图表专页、文本框、自动目录和误报仍需人工核对。“此处补充”“待核实”等只提示复审，真实研究局限表述无需删除。

质检附件记录主稿路径、内容版本、DOCX SHA256、渲染文件路径及SHA256、实际检查页码和检查日期。引用和结构报告自动带入所读DOCX指纹；渲染文件的指纹用环境已有文件校验能力取得。只有实际从该稿导出并检查过的页面才能对应本次视觉结论。哈希只是文件身份记录，不自动证明两个文件的转换关系或审读已经完成。更新字段、改字或重新保存后，核对变动并更新指纹及受影响检查，不能沿用旧文件的通过记录。

依 [质量复核](writing-and-quality.md)完成来源、计算、引用、表达、全文一致性和逐页审查，记录所覆盖的实际稿件。正文篇幅按学校定义核算，分别处理封面、目录、文献等是否计入的规则。

最终交付可编辑完整DOCX、实际使用的证据/引用与必要计算附件、精简质检结果。说明全文状态和真正影响使用的事项；已具备条件时不以“如需我可以继续”停在提纲或局部章节。署名、研究贡献和AI使用披露按真实过程处理，学生本人须理解并复核研究与论证。
