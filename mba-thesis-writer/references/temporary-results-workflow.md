# 先成稿，再替换真实结果

用户要求真实调查完成前先安排全文、试排图表和形成分析时，连续完成可审读研究工作稿。分别记录篇章覆盖和研究证据进度。

## 形成全文

继承开题，整理已有真实资料、已核验文献及待取得的调查证据。按 [问卷设计](questionnaire-and-simulation.md)准备工具；预期结论转为假设，需要临时结果时依 [生成工具](survey-simulator.md)配置。

| 内容 | 工作稿写法 |
|---|---|
| 绪论、综述、已有企业事实 | 用已核验材料完成正式论述 |
| 方法章 | 据实说明当前分析采用的资料、工具与方法；实际调查实施安排写入独立补充说明 |
| 调查分析章 | 用临时图表展开结构和条件式解释，标明数据性质 |
| 方案章 | 完成已有证据支持的措施；依赖假设的措施写明验证条件 |
| 摘要与结论 | 概括已完成研究，清楚区分临时发现与待检验判断 |

文件名和独立说明体现研究稿状态，正文用正式学术表达呈现当前分析。情景内容在方法处说明生成参数与假设，图表注明实际生成来源；“待补”“后续替换”等编辑事项按 [正文与补充说明](manuscript-and-supplement.md)移到独立文档。用标题、段落首句和图表编号关联任务T01等稳定ID，正文无需插入任务占位标记；必要的数据性质在方法和来源处简洁说明，后文不重复编辑提醒。

## 登记替换

沿用project.json：`project.stage=research_draft`、`project.contains_temporary_results=true`。篇章写齐时可另记`chapter_coverage=complete`，它只描述覆盖情况。正式模拟研究中保留的模拟数据与临时待替换数据分别管理。

临时数值和派生值记scenario，情景论断记scenario；现实待验证判断保持pending，实际问卷问题保持in_progress。按 [项目协议](project-schema.md)填写字段。

替换任务复用tasks[]：id、need、purpose、owner、status、blocking，并按需增加temporary_data_ids、draft_locations、required_inputs、replacement_rule。位置覆盖段落、图表、成因、方案、摘要和结论。核心取证任务初始为open且blocking=true。

项目审计对含临时结果的研究稿发出提示，对送审候选报告错误；DOCX审计提示相关待替换文字。结合实际文稿和任务清单判断完成情况。

## 用真实数据更新

保留旧工作稿，核对真实问卷版本、来源与清洗规则，按有效答卷重新分析。用稳定ID定位并更新数字、解释、图表、方案依据、摘要和结论。真实结果支持、部分支持或不支持假设时，分别据实完成论证；研究实质变化按授权调整。

任务中记录实际分析文件、新位置与复核结果，再关闭任务。删除临时分析或改用其他路径时，记录替代依据并完成受影响内容的修改。所有临时内容得到处理后，将contains_temporary_results设为false。

更新内容版本，复核数字、引用、目录及实际分页，重做受影响QA。送审前按独立补充说明定位并逐项检查任务，确认取证、重算和正文修订均已完成，同时清理遗留编辑语句。
