# 成稿引用核对

项目中的来源登记与Word中实际引文要分别检查。`audit_citations.py`直接读取DOCX、TXT或Markdown，针对顺序编码的可读方括号编号查找文中引文与文后条目的缺失、闲置、重复、连续性和首引顺序问题。输入文件哈希随报告保存，使结果可定位到实际检查过的文件。

```text
python "<技能目录>/scripts/audit_citations.py" "<项目目录>/thesis.docx" --style numeric --out "<项目目录>/citation-audit-new.json"
```

需Python3.10+标准库，无联网或其他依赖。报告输出使用新路径，拒绝覆盖输入或既有文件。返回0表示扫描完成且无已识别错误，仍需读取status、warnings与manual_checks；返回1表示发现编号错误，2表示输入/执行错误。`needs_manual_review`不代表引用通过。

默认以完整段落“参考文献”或“References”定位文后列表；可用`--bibliography-heading`指定实际标题。多处同名标题会要求在工作副本明确定位；不要修改原稿来迁就工具。文后至致谢/附录前作为参考文献区，附录及脚注/尾注的可读引文也纳入使用检查。

支持正文`[1]`、`[1,3]`、`[1-3]`及全角方括号，文后每个条目以实际文本`[n]`开头。跨Word文字运行拆开的`[1]`会先按段落合并。Word自动列表编号常不在文本XML中、部分引用域需要先刷新、跨上标运行的特殊范围和各附录独立文献列表不一定适合自动匹配，报告明确保留人工检查。只有文后文字而没有可读取编号时不报告“通过”。

`--style author_year`仅检查文后标题能否定位并提示人工核验，不伪装成实现了著者—出版年匹配。依实际作者、年份、同年字母后缀和文后条目逐项对应。编号样式的方括号也可能是公式或样本编号，命中须返回原位置审读。

文后混用手填编号和自动编号时，工具检查段落直接设置、默认样式和样式继承链；发现尚未展开的编号就保留人工复核状态，不只检查可读的一部分。显式取消编号的段落不视为自动列表。文后没有编号的非空段落会提示检查，区分跨段续写与遗漏编号；真正续写不需为了消除提示改变论文格式。

该工具不格式化参考文献，不证明GB/T 7714-2025及未来现行版的标点、类型代码和必需字段正确，也不核验作者/DOI真实性及引文语义。正式交付仍需按 [证据与引用规则](evidence-and-citations.md)核验来源、类型和现行国标，用实际文稿逐条复核，不能把查到题录或编号闭合当作全文学术合格。
